# Qwen の文字読み取り調査（2026-10-03）

LINE で届いた店舗の画像から、ローカルの Qwen が文字を正しく読めるかを調べた。
材料・正解・結果は `data/qwen_ocr_study/`、再実行は `scripts/qwen_ocr_study.py`。

## 方法

- 画像：取材告知・おすすめ機種・週間スケジュール・新台入替一覧・テキストの案内・横並びの1枚など、性質の違う12枚（PC版LINEの画面から切り出したもの。幅640px前後）
- 正解：Claude が画像を見て、各画像から取れるべき事実（取材名・日付・機種名・時刻・台数など、計69個）を `truth.json` に書いた
- 採点：出力の中に各事実のキーワードがあれば正解（表記ゆれは NFKC・空白無視で吸収）
- Qwen の設定：温度0、思考オフ、`qwen3.8:latest`（27B）を主に、`qwen3.6:35b`（MoE）も一部で比較

## ① Claude は正確に読めるか

- 大きな文字（取材名・日付・オススメ機種・時刻・案内文）はすべて読めた。
- s08 の機種一覧（画面上で1文字5〜6px）は、Claude でも機種名を確実には読めない。台数と一部の機種名だけ。**画像の解像度が足りていない**のが原因で、読み手の問題ではない。

## ❷ Qwen は補助なしで読めないのか

- 大きな文字のポスター型の画像は、補助なしでもほぼ読める（s08・s10を除くと86%、取材名・日付・オススメ機種はほぼ取れる）。
- 失敗の型は2つ：
  1. **繰り返しの暴走**：絵文字の多い文字だけの投稿（s10）で「🔥🔥🔥…」を出し続けて本文を出さない（0/7）。
  2. **小さい文字**：機種一覧（s08）はほぼ読まない（台数だけ）。
- 装飾文字の一部（「でちゃう!取材」のロゴ）を落とす。

## ❸ 補助があれば読めるか、何が効いたか

- **2倍に拡大して縦に分割**（高さ420pxごと、70px重ね）すると、s10 の暴走が消え、ロゴ文字も拾い、s08 も 2→5/10。s08 以外は 98%。
- **Vision の読み取り結果を「誤りを含む参考」として画像と一緒に渡す**と、分割とほぼ同じ精度（98%）で、時間は 2/3。1回の呼び出しで済むので扱いやすい。
- ただし s08 のような小さい文字では、**どちらの補助でも Qwen はもっともらしい嘘の機種名を作る**（「ドラゴンボールZ」「ガンダム00」「とある科学の超電磁砲」など、画像にない機種）。読めない部分を「?」にするよう指示しても守らない。

## 結論と次の手

1. 日常の文字起こしは「**Vision（LLMなし）で全ページを読む → Qwen に画像（2倍）と Vision の文字を渡して整える**」が良い。取材名・日付・オススメ機種・時刻はほぼ取れる（98%）。1枚40秒前後、1日300件なら約3時間（夜間に Mac で回せる）。急ぐなら qwen3.6:35b（1枚10秒前後、やや落ちる）。
2. **小さい文字の一覧は解像度を上げないと誰にも読めない**。PC版LINEで画像をクリックすると元の大きさで開くので、新台一覧のような縦長の画像だけは原寸で保存する仕組みが要る（今は画面の縮小表示を切り出している）。
3. 嘘の機種名を防ぐため、Qwen の出力に出た機種名が Vision の文字にも似た形で出ているかを照合し、どちらにもないものは「要確認」にする。
4. 最終的に欲しいのは全文ではなく「おすすめ機種・取材（名前と日付）・特定日のイベント」なので、次は書き起こしではなく、これらを JSON で抜き出す指示に変えて同じ12枚で採点する。
